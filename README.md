# MVP распределения нагрузки — версия для Railway

Эта папка — отдельная копия проекта для временного размещения на Railway.

Локальная рабочая версия проекта находится вне этой папки и этими настройками не затрагивается.

## Что получится

```text
GitHub repo → Railway service → публичная ссылка → приложение в браузере
```

Railway сам передаст приложению переменную `PORT`, а приложение будет слушать `0.0.0.0`.

Для сохранения Excel-хранилища между перезапусками нужен Railway Volume.

## Структура данных

Основное Excel-хранилище:

```text
app/data/raspredelenie_storage.xlsx
```

Справочник ЮЦ/регионов:

```text
app/справочники.xlsx
```

На Railway рекомендуется хранить рабочий Excel-файл в volume:

```text
/data/raspredelenie_storage.xlsx
```

Если volume пустой, приложение при первом запуске само скопирует стартовый файл из `app/data/raspredelenie_storage.xlsx`.

## Пошаговый запуск на Railway

### 1. Создайте GitHub-репозиторий

1. Создайте новый репозиторий на GitHub.
2. Загрузите в него содержимое папки `railway-mvp-raspredelenie`.
3. Не загружайте `node_modules`, если загружаете файлы вручную через браузер. При работе через git это уже исключено в `.gitignore`.

### 2. Создайте проект Railway

1. Откройте Railway.
2. Нажмите `New Project`.
3. Выберите `Deploy from GitHub repo`.
4. Выберите созданный репозиторий.
5. Дождитесь первой сборки.

Railway должен использовать стандартные команды:

```bash
npm install
npm start
```

Корневой `package.json` сам установит зависимости внутри `app`.

### 3. Подключите постоянное хранилище для Excel

1. В проекте Railway откройте сервис приложения.
2. Добавьте `Volume`.
3. Укажите mount path:

```text
/data
```

4. В переменных сервиса добавьте:

```text
STORAGE_FILE=/data/raspredelenie_storage.xlsx
```

После этого приложение будет писать рабочие изменения в volume, а не во временную файловую систему контейнера.

### 4. Получите публичную ссылку

1. Откройте настройки сервиса.
2. Найдите раздел публичной сети / networking.
3. Сгенерируйте Railway domain.
4. Откройте полученную ссылку в браузере.

### 5. Включите режим засыпания/пробуждения

В настройках сервиса Railway включите serverless/sleep-режим, если он доступен на вашем плане.

Идея такая:

```text
нет трафика → сервис засыпает
пользователь открыл ссылку → Railway будит сервис → приложение запускается
```

Первый запрос после сна может открываться дольше обычного.

## Проверка после деплоя

Откройте в браузере:

```text
https://ваш-домен.up.railway.app/api/data
```

Если всё хорошо, вернётся JSON с данными приложения.

Затем откройте корневую ссылку:

```text
https://ваш-домен.up.railway.app
```

## Локальная проверка перед загрузкой

Из папки `railway-mvp-raspredelenie`:

```bash
npm install
npm test
npm start
```

Открыть:

```text
http://127.0.0.1:8766
```

Проверка volume-режима локально:

```bash
STORAGE_FILE=/tmp/raspredelenie_storage.xlsx npm start
```

## Важные ограничения

1. Railway подходит как временный веб-вариант лучше, чем Codespaces: ссылка может будить сервис.
2. Без volume изменения Excel-файла нельзя считать надёжно сохранёнными.
3. Для постоянной эксплуатации лучше заменить Excel-хранилище на базу данных, а Excel оставить для импорта/экспорта.
4. Если одновременно работают несколько пользователей, Excel-файл остаётся слабым местом: возможны конфликты записи. Для MVP это приемлемо, для промышленной версии лучше база данных.
