# Развёртывание на Render

1. Скопируйте в Git-репозиторий содержимое всей папки проекта, включая `app`,
   `package.json`, `render.yaml` и `docs`. Не добавляйте `.env`, `node_modules`,
   `.DS_Store` и локальные журналы. Частичное копирование отдельных файлов `app`
   не рекомендуется: сервер и браузерный интерфейс должны относиться к одному релизу.
2. В таблице MTS Tabs `Настройки ЮЦ` добавьте поле `Вложения в карточках`
   типа `Выбор` со значениями `Да` и `Нет`. До первого включения пустое значение
   безопасно считается выключенным.
3. Перед отправкой выполните `npm test` из корня проекта.
4. В Render выберите **New > Blueprint** и подключите репозиторий. Render прочитает `render.yaml`.
5. Введите запрошенные секреты:
   - `TABS_API_TOKEN`;
   - `BOOTSTRAP_ADMIN_LOGIN`;
   - `BOOTSTRAP_ADMIN_CODE`.
6. Дождитесь зелёной health check по адресу `/api/health`.
7. После обновления существующего сервиса выберите **Manual Deploy → Deploy latest commit**,
   дождитесь сообщения `Your service is live`, затем обновите приложение без кэша браузера.
8. Выполните первый вход и замените одноразовый код паролем, если сервис создаётся впервые.

Постоянное хранилище Render не требуется. В MTS Tabs хранятся дела, сотрудники,
очереди, отпуска, настройки и данные доступа. Локальный диск содержит только
временный кэш процесса; файловое логирование на Render отключено.

Бесплатный web service засыпает после периода бездействия, поэтому первый запрос
после паузы может быть медленнее. Это ограничение тарифа, а не потеря данных.
