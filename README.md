# MVP распределения нагрузки — версия для Render

Это отдельная копия приложения для публикации через GitHub → Render. Локальная версия приложения не затрагивается.

## Что внутри

- `app/` — само приложение.
- `app/data/raspredelenie_storage.xlsx` — стартовое Excel-хранилище, которое будет скопировано на постоянный диск при первом запуске.
- `render.yaml` — настройки Render Blueprint: сборка, запуск, переменные окружения и постоянный диск.

## Как развернуть через GitHub

1. Создайте новый репозиторий на GitHub.
2. Загрузите в корень репозитория содержимое этой папки `render-mvp-raspredelenie`.
3. В Render выберите `New` → `Blueprint`.
4. Подключите GitHub-репозиторий.
5. Render прочитает файл `render.yaml` и создаст веб-сервис.
6. После завершения деплоя откройте выданную Render-ссылку.

## Что важно про Excel-хранилище

В `render.yaml` задано:

- постоянный диск: `/data`;
- рабочий файл хранилища: `/data/raspredelenie_storage.xlsx`.

При первом запуске, если файла `/data/raspredelenie_storage.xlsx` ещё нет, приложение скопирует туда стартовый файл из `app/data/raspredelenie_storage.xlsx`.

Это нужно, чтобы изменения в делах, сотрудниках, отпусках и статусах сохранялись между перезапусками сервиса.

## Важное ограничение Render

Для сохранения изменений нужен Persistent Disk. У Render постоянные диски доступны для платных web/private/background worker сервисов. Если запустить приложение без постоянного диска, данные в Excel могут сбрасываться после перезапуска или redeploy.

## Если настраивать не через Blueprint, а вручную

Создайте Web Service и укажите:

- Runtime: `Node`
- Build Command: `npm install`
- Start Command: `npm start`
- Environment Variable:
  - `STORAGE_FILE=/data/raspredelenie_storage.xlsx`
- Disk:
  - Mount Path: `/data`
  - Size: `1 GB` или минимальный размер, который предложит Render

## Проверка после деплоя

Откройте:

- главную страницу приложения;
- `/api/data` — должен вернуться JSON с делами, сотрудниками и очередями.

## Безопасность

Сейчас приложение не содержит собственной авторизации. Если ссылка будет доступна из интернета, перед рабочим использованием лучше добавить защиту доступа: например, авторизацию в приложении, доступ через корпоративный VPN или внешний слой защиты.
