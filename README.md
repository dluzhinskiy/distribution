# Распределение нагрузки юридических центров

Актуальная рефакторинговая версия приложения находится в папке
`local-tabs-regional-mvp-refactor`. Исходная рабочая версия сохраняется отдельно.

Приложение работает с удалёнными таблицами MTS Tabs через API и не использует
локальный диск как постоянное хранилище. Это позволяет размещать его на бесплатном
тарифе Render.

## Текущее состояние

- Подключены таблицы:
  - `Настройки ЮЦ`
  - `Региональные закрепления`
  - `Региональные замещения`
  - `Коэффициенты нагрузки`
- Добавлен пункт меню `Настройки`.
- В `Настройках` добавлена редактируемая таблица параметров по выбранному ЮЦ и типу нагрузки:
  - `Активность, дни`
  - `Автозавершение, дни`
  - `Учитывать долг`
  - `Максимальный долг`
  - `Порог перегруза`
- В интерфейсе показываются три категории нагрузки: `судебное`, `административное` и `претензия`.
  Уголовные и банкротные дела используют параметры судебной нагрузки и отдельными строками не показываются.
- Настройки ЮЦ разделены на блоки `Расчёт нагрузки ЮЦ` и `Региональное распределение`.
- На панели добавлен блок `Контроль завершения дел`: дела можно завершить или отложить завершение до выбранной даты.
- В интерфейсе значения `Да/Нет` редактируются тумблерами.
- Отдельная вкладка `Очереди` убрана; долг по типам нагрузки перенесён во вкладку `Сотрудники` → `Доступность и долги`.
- Зависимые настройки и таблицы региональных правил блокируются, если выключен тумблер
  `Учитывать регион при автоматическом назначении`.
- Долг ведётся отдельно по типам нагрузки как неотрицательное число. Старые значения `Да/Нет` и `0/1` также распознаются.
- Добавлен серверный кэш данных:
  - каждый экран запрашивает только нужные ему таблицы, остальные догружаются при первом открытии соответствующей вкладки;
  - параллельные запросы одной таблицы объединяются в одно чтение;
  - после точечной записи кэш обновляется сразу без повторного чтения всей таблицы;
  - настройки/региональные правила кэшируются дольше, чем рабочие таблицы.
- Справочник регионов кэшируется отдельно, поэтому переходы между вкладками не запускают его повторное полное чтение.
- Выдача кода доступа, смена роли, карточка дела и долги очереди записываются адресно, без полной перезаписи таблиц.
- Реестр дел использует серверную пагинацию по 150 строк: поиск и фильтры применяются ко всему реестру, но браузер получает только текущую страницу.
- Для реестра используется рабочая проекция без поля `Движение дела` и вложений; полная карточка загружается отдельно.
- Автоматически повторяются только безопасные чтения и адресные идемпотентные изменения. После неоднозначного `POST` приложение проверяет бизнес-ключи и не создаёт дубли вслепую.
- `X-Operation-Id` защищает сервер от повторной обработки одного клиентского изменения.
- Каждый HTTP-ответ содержит `Server-Timing`, а `/api/cache-status` показывает время и объём последних чтений MTS Tabs.
- После запуска сервер в фоне прогревает таблицы стартового дэшборда и справочник регионов. Прогрев не задерживает health-check Render и отключается через `FAST_ENGINE_CACHE_WARMUP=0`.
- После успешной загрузки облегчённого дэшборда сервер сначала прогревает рабочую проекцию реестра, затем полные карточки дел. Отложенный прогрев управляется через `FAST_ENGINE_FULL_CASES_WARMUP` и `FAST_ENGINE_FULL_CASES_WARMUP_DELAY_MS`; параллельные запросы используют уже выполняющееся чтение.
- Рабочий журнал действий полностью исключён: приложение не читает и не изменяет таблицу `Журнал` в MTS Tabs.
- Добавлен переключатель приведённой нагрузки на историческом дэшборде. В этом режиме полоса показывает единый итог, а коэффициенты выведены отдельной легендой. Коэффициенты глобальны, редактируются только администратором и не влияют на назначение.
- Алгоритм автоназначения учитывает региональные закрепления и отдельную таблицу замещений:
  - если учёт региона выключен, работает общая очередь выбранного ЮЦ и типа нагрузки;
  - если учёт региона включён, сначала выбираются доступные сотрудники, закреплённые за регионом и типом нагрузки;
  - если для региона и типа нет закреплений, приложение переходит в общую очередь или останавливает автоназначение согласно настройке ЮЦ;
  - если закреплённые сотрудники недоступны, приложение использует настроенное замещение, общую очередь либо останавливает автоназначение;
  - назначение вне региональной группы выполняется автоматически, когда группа перегружена сверх порога выбранного типа нагрузки;
  - перегруз считается как разница между минимальной нагрузкой региональной группы и минимальной нагрузкой доступных сотрудников вне региона;
  - при сравнении учитываются только дела соответствующей категории нагрузки;
  - если вся основная региональная группа недоступна, формируется резервная очередь из активных строк таблицы `Региональные замещения`;
  - роль доступа `Заместитель` не связана с этой резервной очередью.
- Уведомления сотрудникам о назначении дел пока не реализованы.

## Настройки в MTS Tabs

### Таблица `Настройки`

Одна строка соответствует сочетанию `ЮЦ + Тип дела`. Используемые приложением столбцы:

- `ЮЦ`
- `Тип дела`
- `Активность, дни`
- `Автозавершение, дни`
- `Учитывать долг`
- `Максимальный долг`
- `Порог перегруза`

Порог перегруза задаётся только для трёх категорий: `судебное`, `административное`
и `претензия`. Уголовные и банкротные дела используют строку `судебное`.
Пустое или некорректное значение порога в расчёте безопасно заменяется значением `5`.

### Таблица `Настройки ЮЦ`

Одна строка соответствует одному ЮЦ. Используемые приложением столбцы:

- `Название`
- `ЮЦ`
- `Региональные очереди вкл\выкл`
- `Учитывать неактивные незавершенные в нагрузке`
- `Регион не настроен`
- `Региональные юристы недоступны`

В интерфейсе техническое поле `Региональные очереди вкл\выкл` называется
`Учитывать регион при автоматическом назначении`.

После обновления приложения из таблицы `Настройки ЮЦ` можно удалить устаревшие столбцы:

- `Порог перегруза`
- `Считать перегруз по`
- `Автоназначение вне региона вкл/выкл`

Приложение их больше не читает и не записывает. Переименовывать оставшиеся столбцы
в MTS Tabs не нужно: понятные названия применяются только в интерфейсе.

### Глобальные коэффициенты

Таблица `Коэффициенты нагрузки` содержит `Тип нагрузки` и `Коэффициент` для пяти
типов дел: судебного, административного, претензии, уголовного и банкротного.
Коэффициенты применяются только на историческом дэшборде, пересчитывают всю историю
по текущим значениям и не влияют на назначение, очереди или перегруз.

## Первичный вход и роли

В локальной версии включены роли `Сотрудник`, `Руководитель`, `Заместитель` и `Администратор`.

- Все авторизованные пользователи могут читать дела и документы всех ЮЦ.
- Сотрудник изменяет только собственные дела своего ЮЦ.
- Руководитель и заместитель управляют данными своего ЮЦ, а другие ЮЦ просматривают без права изменения.
- Руководитель и заместитель могут изменять параметры нагрузки и регионального распределения своего ЮЦ.
- Администратор управляет всеми ЮЦ.
- Кнопка `Выход` завершает только пользовательский сеанс и не останавливает сервер.

Для первого входа системной записи `EMP-000` заполните в локальном `.env`:

`AUTH_SESSION_SECRET` — случайная строка не короче 32 символов;
`BOOTSTRAP_ADMIN_LOGIN=sdluzhi`;
`BOOTSTRAP_ADMIN_CODE` — одноразовый код, который будет использован только при первоначальной установке пароля.

После первого входа код больше не принимается. Администратор в разделе «Доступы» выдаёт сотрудникам новые одноразовые коды сроком на семь дней и назначает роли. В MTS Tabs сохраняются только хеши паролей и кодов.

## Запуск

Из этой папки:

```bash
./start_local_regional.sh
```

По умолчанию приложение откроется на:

```text
http://127.0.0.1:8767
```

Порт выбран `8767`, чтобы не конфликтовать с локальной Excel-версией и старой API-сборкой.

## Подготовка к Render

Приложение не использует локальный диск как постоянное хранилище: рабочие данные,
учётные записи и настройки находятся в MTS Tabs. На Render сервер слушает
`0.0.0.0:$PORT`, локальная запись технических ошибок по умолчанию отключена, а для проверки здоровья
доступен `GET /api/health`. Кэш остаётся только ускорителем и безопасно теряется
при перезапуске экземпляра.

В корне есть `render.yaml`, который создаёт бесплатный Node web service. После
подключения репозитория нужно ввести секреты `TABS_API_TOKEN`,
`BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_CODE`; `AUTH_SESSION_SECRET` Render
сгенерирует сам. Все ID таблиц берутся из безопасных значений по
умолчанию или могут быть переопределены переменными окружения.

Записи в одном экземпляре сериализуются: перед каждой мутацией
сервер принудительно получает свежие данные MTS Tabs. Расчёт
рекомендации, вход, выход и preview-запросы не блокируют эту очередь.

Автономные проверки запускаются командой `npm test`. Проверка подключения к
реальному MTS Tabs вынесена отдельно: `npm run test:integration:tabs`. Она только
читает таблицы и требует `TABS_API_TOKEN`.

В текущем наборе один ранее известный тест импорта
`case import apply writes only changed rows and returns a compact delta` завершается
расхождением `0 !== 2`. Он не связан с настройками перегруза или региональным
распределением; профильные доменные, авторизационные и маршрутные тесты проходят.

## Структура серверной части

`app/server.mjs` остаётся точкой сборки приложения: создаёт зависимости,
проверяет сеанс и запускает HTTP-сервер. Предметные обработчики вынесены отдельно:

- `app/routes/case-routes.mjs` — карточки дел, назначение и документы;
- `app/routes/case-import-routes.mjs` — предварительная проверка и применение импорта дел;
- `app/routes/vacation-routes.mjs` — отпуска и их импорт;
- `app/routes/settings-routes.mjs` — настройки ЮЦ, региональные закрепления и замещения;
- `app/lib/table-cache.mjs` — кэш чтения MTS Tabs;
- `app/lib/http-utils.mjs` — чтение HTTP-запросов, безопасные JSON-ответы и статические файлы;
- `app/lib/access-policy.mjs` — единая матрица прав доступа;
- `app/lib/regional-rules.mjs` — нормализация и проверка региональных правил;
- `app/lib/distribution.mjs` — расчёт очередей, рекомендация и назначение;
- `app/lib/case-lifecycle.mjs` — смена ответственного, завершение, отложение, удаление и восстановление;
- `app/lib/vacations.mjs` — доменные операции с отпусками;
- `app/lib/domain-schema.mjs` — имена полей и ключей настроек;
- `app/lib/domain-values.mjs` — общая нормализация доменных значений, ФИО и дат;
- `app/lib/errors.mjs` и `app/lib/validation.mjs` — единые API-ошибки, валидация и allowlist полей;
- `app/lib/write-coordinator.mjs` — очередь и защита от конкурирующих записей;
- `app/lib/load-coefficients.mjs` — валидация глобальных коэффициентов;
- `app/public/lib/load-coefficients.js` — изолированный расчёт приведённой нагрузки;
- `app/public/lib/api-client.js` — единый HTTP-клиент и идентификаторы операций;
- `app/public/lib/app-state.js` — фабрика состояния клиента;
- `app/public/lib/ui-utils.js` — тестируемые клиентские функции форматирования и нормализации.

Маршруты получают внешние зависимости через фабрики. Поэтому права доступа и
операции маршрутизации проверяются автономно, без записи в рабочие таблицы.

## Импорт дел

Поле `Движение дела` импортируется и подтверждается вместе с остальными полями
дела в общем потоке сохранения. Отдельного пользовательского шага или фоновой
очереди для этого поля нет.

Импорт оптимизирован для крупных консолидированных отчётов:

- дубли в реестре и внутри файла ищутся по индексам, без повторного перебора всех дел для каждой строки;
- исключённые строки учитываются счётчиком и не передаются браузеру целиком;
- предварительный просмотр запоминает версии кэша дел и сотрудников;
- при применении новые дела создаются пакетно, а существующие обновляются адресно;
- после подтверждения сервер возвращает только созданные/изменённые дела и пересчитанный небольшой список сотрудников, а не весь реестр.
